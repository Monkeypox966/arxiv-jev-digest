# 项目链接与作者机构：覆盖范围

元数据查找独立于相关性判断和中文摘要生成。每篇相关性达标论文先补资料，再进行机构过滤和 Top K 排序；摘要仍只依据原始摘要生成。

## 查找流程

1. 已有人工核实记录优先使用。
2. 读取 arXiv abs 首页，检查摘要和 Comments 的链接，包括标签只写 `this https URL` 的链接。
3. 读取论文 HTML，保留正文链接并去掉参考文献区域。
4. 项目链接缺失、作者机构映射不完整，或者 HTML 显示机构标记损坏时，继续查 PDF。PDF 提取前两页署名，并扫描最多 40 页正文的可点击链接和明文 URL；遇到 References / Bibliography 停止，避免把引用项目当作本文项目。
5. 仍有作者机构缺失、且已有确认的项目链接时，读取该项目页。通过论文标题，或论文 ID 与作者组合核对身份，才允许提取机构。每篇最多读一个项目页，不递归抓取作者主页或其他链接。
6. 按字段合并：找到的项目链接不会因后续 PDF 缺失而消失；补查 PDF 时优先保留 PDF 对已映射作者的署名；项目页仅补尚未映射的作者，不覆盖论文中已有的对应关系。只有学校 logo、赞助方或邮箱域名时，不应推断全部作者机构。

`project_source` 记录项目链接的发现来源，每项 `affiliations[].source` 记录机构来源；原有人工记录没有细分字段时仍保留整条记录的来源列表，不猜测发现位置。HTML、PDF 或项目页某一步失败，会保留之前得到的信息并在 notes 中记录缺失/失败。

访问外部项目页会检查公共网络地址、每次重定向、超时、页面类型和 2 MiB 大小上限。PDF 默认限制 25 MiB；均使用有限页数，不运行页面脚本。新的提取策略、摘要和相关提取配置进入元数据缓存键，避免直接复用旧策略的结果。

配置位于 `config.toml`：

```toml
[enrichment]
enabled = true
timeout_seconds = 45
max_pdf_mb = 25
max_pdf_pages = 40
follow_project_page = true
```

## 2026-10-24 的真实样例核查

下载三篇真实论文的 abs、HTML、PDF，提取文本并渲染 PDF 首页核实。候选链接提取检查使用实际下载文件；多来源合并与失败回退使用无网络、无模型的回归测试。这轮没有调用付费模型，也没有重发邮件，不能据此宣称模型对任意论文都能正确识别。

| 样例 | 实际项目位置 | 机构问题 |
| --- | --- | --- |
| [LaTER / 2605.07315](https://arxiv.org/abs/2605.07315) | abs 摘要末尾的 [GitHub 仓库](https://github.com/TioeAre/LaTER) | PDF 首页有机构；Yuchen Liu 没有清楚的机构上标，不应猜测。此文为 cs.CL，仅用于提取验证，不应进入 cs.RO 日报。 |
| [BeyondMimic / 2508.08241](https://arxiv.org/abs/2508.08241) | abs Comments 中的[项目网站](https://beyondmimic.github.io/) | 当前 v4 的 HTML 丢失多数作者机构标记，PDF 首页有完整 Berkeley / Stanford 对应关系。项目网站比当前论文少一位作者。 |
| [Humanoid-GPT / 2606.03985](https://arxiv.org/abs/2606.03985) | abs 无项目；[HTML](https://arxiv.org/html/2606.03985v1) 和 PDF 首页有[项目网站](https://qizekun.github.io/Humanoid-GPT/)及代码 | HTML 的作者机构映射损坏；PDF 可用。项目网站与论文还有真实署名差异。 |

Humanoid-GPT 的 [PDF](https://arxiv.org/pdf/2606.03985) 将 Xuchuan Chen 标为清华 + Galbot，将 Sikai Liang 标为 Galbot + 上海交大；项目网站分别为 Galbot + 北航、仅 Galbot。这说明项目页应作为补缺来源。自动流程不是对所有来源进行全面交叉审计：已有完整论文署名时，不会为了发现冲突而强制抓项目页。

新增回归覆盖 abs 摘要 / Comments、普通锚点、HTML/PDF 字段合并、部分作者映射、项目身份不符、后续失败保留结果、PDF 第三页明文链接、参考文献排除、扫描限额和外链访问边界。原有筛选、摘要和邮件去重测试同时保留。

## 尚不能保证的情况

- 扫描 PDF、图片中的署名或二维码，以及缺乏可提取文字的网页：尚无 OCR / 二维码识别。
- 项目页完全依赖 JavaScript、需要登录、反爬拦截、已下线，或机构仅在作者个人主页：不会绕过限制或递归搜索。
- 链接在第 40 页之后，或位于参考文献之后的附录：当前有限扫描可能漏掉。
- 模型对复杂上标、多机构、同名作者仍可能判断错误；机构字串存在、作者名合法，并不能完全证明对应关系正确。
- 正文中的代码、数据集、作者主页和本论文项目仍可能混淆；模型被要求只选本文项目，无法给出百分之百正确性保证。
- 部分缺失的结果仍可能进入缓存；目前没有字段级短缓存、网页更新时间感知或论文修订版本检查点。

## 后续优先级

1. 元数据按字段区分“已确认、未发现、暂时失败”，缺失/失败短缓存，关联 arXiv 修订版本，并在报告显示完整度。
2. 将机构“未收录”与“低分”设置成独立策略，提供待核查候选池，降低名单漏收导致的误删。
3. 按最后成功公告日期补抓漏跑批次；目前 latest 模式仍只取最新一批，滚动 API 模式可手动用于补抓。
4. 增加元数据模型调用、token、总体预算、来源失败率和关键失败通知，避免多来源查找成本不透明。
5. 有明确需要时再增加受限网页搜索、OCR、TeX 源文件解析和浏览器渲染，并继续保留出处与缺失状态。
